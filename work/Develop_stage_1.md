# Разработка этап 1
**Создание системы учета**
Данных этап предполагая начала разработки проекта и заложение основ для дальнейшего добавления функционала в последующих этапах. Система учета представляет собой базу данных организованную из определенных сущностей, определенный набор операции по манипуляции с этими сущностями и интерфейс для вызова этих операций.
## Структура системы учёта
см. [структура](<../docs_project/Architecture.md#Структура сервиса "Этап 1">)
## Декомпозиция задач на технические задачи
см. [задачи 1 этапа](<./Develop.md#Задачи этапа>)
**Технические задачи:**
1. Создание базы данных с необходимой структурой;

## Техническая задача 1 - Методы взаимодействия с базой данных
Необходимо создать возможность взаимодействия пользователя с сущностями базы данных через интерфейс web интерфейс. Взаимодействие недолжно нарушать работу самой базы данных и приводить к порче уже имеющийся информации в ней и некорректному выводу этой информации. Для этого необходимо определить функции (возможности взаимодействия) и правила по которым взаимодействие с базой данных будет осуществляться. Часть правил и ограничений уже заложена в базу данных, например уникальность полей некоторых столбцов, а также ограничение на нулевое значение.
### Список функций
#### Создание, редактирование, удаление, получение Location "Объектов"
Данный комплекс функций должен позволять пользователю добавлять записи в таблицу "locations", а также удалять, изменять и получать их из базы данных.
**Правила и требования:**
 - Уникальность наименования;
 - Корректное удаление записей;
 - Корректное обновление полей записи определенных пользователем.
#### Создание, редактирование, удаление, получение Asset "Материальных ценностей"
Данный комплекс функций должен позволять пользователю добавлять записи в таблицу "assests", а также удалять, изменять и получать их из базы данных.
**Правила и требования:**
 - Уникальность наименования;
 - Корректное удаление записей;
 - Корректное обновление полей записи определенных пользователем.
#### Создание, редактирование, удаление, получение MoveLog "Движений" и DetailMoveLog "Детали движения"
Данный комплекс функций должен позволять пользователю добавлять записи в таблицу "movelog" совместно с таблицей "detailmovelog", а также удалять, изменять и получать из базы данных их.
**Правила и требования**:
- Не позволять добавлять такие записи что, уводили бы количество материальных ценностей на объекте в отрицательное значение;
- Не оставлять записи в таблице "движения" без привязки к записям в таблице "детали движения";
- Если поле  "тип" в записи "движения" определено как "поставка", то поле "откуда" должно быть пустым, а поле "куда" обязательно заполнено;
- Если поле "тип" в записи "движения" определено как "перемещения", то поля "откуда" и "куда" обязательно должны заполнены и отличаться друг от друга;
## Техническая задача 2 - Методы анализа
### Список функций
Необходимо создать возможность для пользователя быстро получать обобщенную информацию о количестве и местонахождении тех или иных материальных ценностей. То есть анализ подразумевает ответы наследующие вопросы:
- Сколько материальных ценностей в данный момент находится на конкретном объекте?
- Где и в каком количестве находятся конкретные материальные ценности?
- Какова история движения конкретных материальных ценностей?
- Какова история движения на конкретном объекте?
- Сколько всего было заявлено конкретных материалов на конкретный объект?
- Какова разница между конкретных заявленных материалов на конкретный объект и поставленных?
Всю информацию для этих вопросов возможно получить используя определенные запросы к БД и фильтрацию данных.
- Вывод остатков материальных ценностей:
	- всех относительно объектов;
	- просмотр конкретных ценностей по объектам с временным параметром;
	- просмотр средств относительно

### Asset "Материальные ценности"
См. [Asset - таблица "материальные ценности"](<../docs_project/modules/backend/Data_base.md#Asset - Таблица «Материальные ценности»>)

При создании Asset в базе данных нужно указывать:

- **Ед.Изм** - из заранее заданных;
- **Тип** - из заранее заданных;
- **Примечание** - необязательное поле
